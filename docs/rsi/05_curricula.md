# 05｜自博弈、任务生成与环境学习

[返回总览](README.md) · 本章收录 P17–P20、P55–P56。

固定题库上的学习可以提升能力，但难以持续提供恰当难度的新信号。本章关注“谁出题、如何判题、如何知道题目值得学”。课程演化是 RSI 的重要组成部分；它与改进器代码自修改可以独立发生。

<a id="p17"></a>
## P17｜DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning

**文献**：DeepSeek-AI 等，2025 首稿。[原文](https://arxiv.org/abs/2501.12948)。

**问题与方法**：大规模结果奖励训练能否强化推理？R1-Zero 在基础模型上直接进行强化学习，观察到更长推理和自检查等行为；R1 在此基础上结合冷启动数据及多阶段训练改善可读性与整体表现。

**证据**：数学、代码和推理任务上的实验使可验证奖励成为后训练研究的重要路线。它展示训练可以增强反思行为，而不是只靠提示词要求反思。

**边界**：R1-Zero 不使用冷启动 SFT，不意味着不需要预训练、训练问题和奖励设计。R1 与 R1-Zero 的设置不能混用；论文也不展示训练算法的自主递归重写。

**连接**：由 [P11 ReST-EM](04_self_training.md#p11) 的验证筛选过渡到强化学习；[P18](#p18) 进一步减少人工题目依赖；与 [P42 SCoRe](09_evaluation.md#p42) 对照专门学习自纠错与一般推理训练。

**研究启发**：把权重学习、输出长度、更多采样与自纠错贡献拆开测，不把所有收益归因于“出现反思”。

<a id="p18"></a>
## P18｜Absolute Zero: Reinforced Self-play Reasoning with Zero Data

**文献**：Andrew Zhao 等，2025。[原文](https://arxiv.org/abs/2505.03335) · [方法正文](https://arxiv.org/html/2505.03335v1)。

**问题**：若持续依赖人工题库，后训练可能遇到课程瓶颈。

**方法**：Absolute Zero Reasoner（AZR）让同一个模型承担出题者和解题者，在程序、输入、输出的关系上构造演绎、归纳和溯因任务；执行环境负责检查任务及答案，并提供学习信号。课程和求解策略共同更新。

**证据**：作者在多种基础模型和规模上观察到数学及代码推理收益。这里的“零数据”应限定为该自博弈训练阶段不依赖外部人工题目/答案，不能扩大为没有预训练知识。

**边界**：程序执行正确性受输入覆盖、终止条件和任务构造影响；外层奖励与任务类型仍人工定义。代码域中的收益是否能迁移到难以验证的现实任务需要进一步检验。

**连接**：[P06 AlphaZero](03_foundations.md#p06) 提供自博弈与环境反馈的参照；[P07 POET](03_foundations.md#p07) 提供课程共同演化视角；与 [P19](#p19) 的多数票伪标签形成关键对比。

**研究启发**：把“可执行题目比例”“真实可解性”“课程覆盖”“学习后独立测试收益”分别记录；中等通过率并不自动代表最大学习价值。

<a id="p19"></a>
## P19｜R-Zero: Self-Evolving Reasoning LLM from Zero Data

**文献**：Chengsong Huang 等，2025。[原文](https://arxiv.org/abs/2508.05004) · [方法正文](https://arxiv.org/html/2508.05004v1)。

**问题与方法**：从同一基础模型初始化 Challenger 与 Solver，分别训练。Challenger 提出求解器不太容易也不至于完全无法处理的问题；Solver 多次回答，多数票提供伪标签，并经筛选形成下一轮训练数据。

**证据**：论文在数学与通用推理评估中报告收益，并分析任务难度与数据质量随迭代的变化。

**最关键的区别**：多数票衡量的是样本之间的一致性，不是独立正确性证明。论文正文也讨论更难问题上伪标签质量下降。故不能把本篇与 AZR 的执行验证写成同一种“无人工真值且完全可靠”的方法。

**连接**：与 [P18](#p18) 同属课程—求解共同演化，但质量锚点不同；与 [P13 Self-Rewarding](04_self_training.md#p13) 共享同源信号风险；[P49–P50](09_evaluation.md#p49) 提供长期递归数据训练的背景。

**研究启发**：比较同模型多数票、不同模型交叉判定、程序化验证三种信号；在独立可检查子集上测伪标签精度，而非只测内部一致率。

<a id="p20"></a>
## P20｜Agent0: Unleashing Self-Evolving Agents from Zero Data via Tool-Integrated Reasoning

**文献**：Peng Xia 等，2025-11 首稿；近期代表作。[原文](https://arxiv.org/abs/2511.16043)。

**问题与方法**：自课程如果只围绕模型原有的内部能力，可能难以扩展复杂交互。Agent0 让课程智能体与执行智能体共同演化，执行者使用工具，课程者因此要提出更具挑战且适合工具使用的任务。

**证据**：作者报告数学和通用推理基准上的改进。应将这些结果理解为给定模型和工具设置中的自课程证据，而非通用自主智能的完成。

**边界**：工具本身携带外部能力与信息；“零数据”仍不取消预训练与工具先验。本笔记主要核对摘要，未逐项审计其奖励实现，不据此声称所有奖励均为客观验证。

**连接**：将 [P19 R-Zero](#p19) 的双角色课程与 [P39 Toolformer](04_self_training.md#p39) 的工具能力相联系；与 [P56 AgentGym](#p56) 比较任务生成和环境轨迹学习的不同重点。

**研究启发**：做工具可用性迁移：训练阶段有工具、评测工具变化或失效时，提升来自通用能力还是固定工具依赖？

<a id="p56"></a>
## P56｜AgentGym: Evolving Large Language Model-based Agents across Diverse Environments

**文献**：Zhiheng Xi 等，2024。[原文](https://arxiv.org/abs/2406.04151)。

**问题与方法**：单一环境中的轨迹训练容易培养专才。AgentGym 提供统一交互接口、多样环境、初始轨迹与评估套件，并用 AgentEvol 方法探索跨任务、跨环境的自演化训练。

**证据**：作者在多环境评估中展示进步，并开放平台、数据、模型与算法。其价值既是方法，也是一套可用于检查环境泛化的基础设施。

**边界**：存在初始高质量轨迹与人类设计的环境；不是从零监督起步。训练得到更好的策略仍不等于自改训练流程。

**连接**：承接 [P46 AgentBench](09_evaluation.md#p46) 对交互能力的评价需求；连接 [P11](04_self_training.md#p11) 的成功轨迹自训练与 [P55](#p55) 的高效探索。

**研究启发**：采用留一环境类型测试，区分同任务族插值与新的环境机制适应。

<a id="p55"></a>
## P55｜AgentEvolver: Towards Efficient Self-Evolving Agent System

**文献**：Yunpeng Zhai 等，2025-11 首稿；近期代表作。[原文](https://arxiv.org/abs/2511.10395)。

**问题与方法**：智能体训练面临造题、无效探索与轨迹利用率三重成本。论文组合 self-questioning、self-navigating、self-attributing，分别面向自主任务生成、经验复用与引导探索、状态/动作贡献归因。

**证据**：作者围绕学习效率与环境任务表现开展实验。它把自演化从单纯“多生成一点数据”扩展到训练流程中的多个环节。

**边界**：各机制仍嵌在预定义框架中；需要消融分开判断数据规模、导航策略和归因带来的收益。本文与 2026 年另一篇同名 *AgentEvolver: System-Wide Self-Evolution Through Task Execution* 不是同一文献，不混用结果。

**连接**：与 [P56](#p56) 的环境学习相接；将 [P18](#p18) 的课程问题拓展到探索及信用分配；与 [P51](10_frontier.md#p51) 对照“改进学习流程的固定模块”与“模块改进机制本身可编辑”。

**研究启发**：在固定环境交互次数下做因子消融，检查每个模块是否减少无效交互，而非只是增加计算。

## 本路线的开放问题

一个有价值的课程至少需要满足：有效、具有适当挑战、覆盖不同能力、能产生可迁移收益。四者不能用单个“解题成功率接近 50%”替代。歧义题同样可能得到中间成功率；重复题可能很容易学却没有新价值。

建议先在可验证领域研究课程质量，再扩展开放任务。与代码 RSI 结合时，可让生成器产生新的开发任务，但必须保留独立、固定或密封更新的审计任务，否则系统可能通过降低任务难度获得虚假的进步。
