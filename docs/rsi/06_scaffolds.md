# 06｜反思、记忆与提示词进化

[返回总览](README.md) · 本章收录 P21–P28、P59。

这组工作把学习的位置从参数扩展到上下文、经验、技能与提示词。其中，自反馈改善当前答案、记忆改善后续尝试、优化器改善整个提示程序，是三种不同的持久性。Promptbreeder 进一步让“修改提示词的提示词”也演化，是容易在 RSI 阅读中漏掉的重要连接点。

<a id="p21"></a>
## P21｜ReAct: Synergizing Reasoning and Acting in Language Models

**文献**：Shunyu Yao 等，2022 首稿，ICLR 2023。[原文](https://arxiv.org/abs/2210.03629)。

**问题与方法**：只推理可能缺少外部事实，只行动又难以维持计划。ReAct 交替产生推理、行动和环境观察，让模型据反馈调整后续决策。

**证据**：在问答、事实核查及交互任务上展示效果。它提供了后续语言智能体常用的交互结构，使环境反馈可进入推理过程。

**边界**：一次任务中的计划变化不等于跨任务学习；默认没有把每次经历持久写回参数或元优化器。额外工具信息也应计入能力来源。

**连接**：[P23 Reflexion](#p23) 为交互循环增加可回用反思；[P40 SWE-agent](07_recursive_agents.md#p40) 把交互接口用于软件工程；[P39 Toolformer](04_self_training.md#p39) 则从训练侧学会工具调用。

**研究启发**：把环境观察、反思文本与持久更新分别消融，检查系统究竟从哪里得到新信息。

<a id="p22"></a>
## P22｜Self-Refine: Iterative Refinement with Self-Feedback

**文献**：Aman Madaan 等，2023。[原文](https://arxiv.org/abs/2303.17651)。

**问题与方法**：模型首轮输出未必最好。使用同一模型依次生成初稿、提出反馈、据此修订，循环数次；不需要额外参数训练。

**证据**：作者在七类任务中比较单次生成与迭代修订，观察到人类偏好或自动指标收益。它说明推理时反馈可以有用，尤其当改进标准可以通过语言描述时。

**边界**：收益依任务、反馈和评价协议而变；更多调用带来更多计算。不能由此推出模型在没有外部信号时普遍能发现自己的逻辑错误，也没有默认的跨任务持久学习。

**连接**：与 [P41 Cannot Self-Correct](09_evaluation.md#p41) 配对阅读；后者检查更严格的内在推理纠错设置，并非简单否定一切迭代修订。[P42 SCoRe](09_evaluation.md#p42) 转向训练纠错能力。

**研究启发**：比较相同调用预算下的修订、独立重采样与 best-of-N，并同时测量“改错”和“把对的改错”。

<a id="p23"></a>
## P23｜Reflexion: Language Agents with Verbal Reinforcement Learning

**文献**：Noah Shinn 等，2023。[原文](https://arxiv.org/abs/2303.11366)。

**问题与方法**：不进行昂贵梯度更新，智能体怎样利用试错？把成功/失败或文本反馈转换成语言反思，放入情景记忆，在后续尝试中指导行为。

**证据**：在决策、代码和推理实验中观察到收益。论文使用“verbal reinforcement learning”强调语言反馈，但不能据此假定模型权重发生了 RL 更新。

**边界**：实验中的记忆范围、重试预算和反馈可见性很重要；对同一任务重试的成绩不等于从未见过该任务的一次性解答能力。错误反思也可能形成持久偏见。

**连接**：在 [P21 ReAct](#p21) 交互结构上理解记忆的作用；[P24 Voyager](#p24) 存储可执行技能；[P28 GEPA](#p28) 把轨迹反思转化为跨样本可复用提示。

**研究启发**：将记忆按来源、适用条件和失败反例组织，研究有害记忆的识别与遗忘。

<a id="p24"></a>
## P24｜Voyager: An Open-Ended Embodied Agent with Large Language Models

**文献**：Guanzhi Wang 等，2023。[原文](https://arxiv.org/abs/2305.16291)。

**问题与方法**：怎样在长期交互中积累能力？Voyager 在 Minecraft 中结合自动课程、可执行技能库和基于环境/执行反馈的代码修订；冻结基础模型，检索并组合已有技能。

**证据**：论文展示探索、物品获取及在新世界复用技能的收益。能力的载体是可以反复调用的程序，不只是临时对话历史。

**边界**：环境、技能接口和课程框架仍预设；技能增长不直接证明生成技能的算法也在改进。技能越多可能带来检索与组合成本，不能只统计库大小。

**连接**：将 [P07 POET](03_foundations.md#p07) 的开放课程与 [P23](#p23) 的经验积累相连；[P32 SICA](07_recursive_agents.md#p32) 与 [P33 DGM](07_recursive_agents.md#p33) 把可修改代码扩展到智能体自身。

**研究启发**：测量技能在独立任务上的边际贡献，删除高频但无增益的技能，防止“记住越来越多”被误作“学得越来越好”。

<a id="p25"></a>
## P25｜DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines

**文献**：Omar Khattab 等，2023 首稿。[原文](https://arxiv.org/abs/2310.03714)。

**问题与方法**：硬编码提示链难以系统优化。DSPy 用声明式模块表达语言模型计算图，根据任务指标收集/构造示例并编译优化流程，分离程序逻辑与提示实现。

**证据**：论文展示数学、多跳检索及复杂问答等案例中的优化收益。重要贡献是给提示程序一个可优化、可替换的表示层。

**边界**：优化指标、开发数据与编译器仍外部给定；标题中的 self-improving 不自动意味着编译器会改写自己。当前软件库的能力也不能全部归给原始论文。

**连接**：与 [P26 OPRO](#p26) 对照程序化优化与直接提示优化；为理解 [P27 TextGrad](#p27)、[P28 GEPA](#p28) 的复合系统优化提供基础；[P30 ADAS](07_recursive_agents.md#p30) 扩展到代码化设计。

**研究启发**：先定义清楚可优化变量，再研究 RSI；表示方式本身会约束能发现什么改进。

<a id="p26"></a>
## P26｜Large Language Models as Optimizers（OPRO）

**文献**：Chengrun Yang 等，2023 首稿，ICLR 2024。[原文](https://arxiv.org/abs/2309.03409)。

**问题与方法**：没有可用梯度时，LLM 能否依据历史候选与得分提出新解？把优化目标、已有解及分数放入提示，生成新候选、评价并更新历史。主要应用是提示词搜索。

**证据**：论文既展示数值/组合问题示例，也在推理提示优化中报告收益。语言模型在这里充当基于历史的候选生成器。

**边界**：有限任务上的有效搜索不保证一般优化能力；搜索记录增长及评估成本须计入。默认优化循环和改进提示本身没有递归演化。

**连接**：向 [P59 Promptbreeder](#p59) 接“改进提示也可进化”；向 [P28 GEPA](#p28) 接利用执行轨迹与候选互补性；向 [P29 STOP](07_recursive_agents.md#p29) 接代码表达的优化过程。

**研究启发**：比较只提供标量分数、提供错误类别、提供完整轨迹三种反馈的信息效率。

<a id="p59"></a>
## P59｜Promptbreeder: Self-Referential Self-Improvement Via Prompt Evolution

**文献**：Chrisantha Fernando 等，2023 首稿。[原文](https://arxiv.org/abs/2309.16797)。

**问题与方法**：如何减少对手工任务提示及手工变异策略的依赖？维护任务提示种群，由 mutation-prompts 指导语言模型修改它们；这些用于变异的提示也在进化中被生成和改进。

**证据**：作者在算术、常识推理和分类任务上报告优于部分手工提示策略的结果。它明确包含任务层和变异策略层两个可变对象。

**边界**：基础模型、适应度数据和外层进化程序仍固定；发现有效变异提示不等于已经证明长期、跨任务的改进速度不断增加。

**连接**：是 [P26 OPRO](#p26) 与 [P29 STOP](07_recursive_agents.md#p29) 之间很有价值的机制桥梁；与 [P51 Hyperagents](10_frontier.md#p51) 对照“提示层元机制”和“代码层元机制”。

**研究启发**：固定任务提示后单独迁移变异提示，检验元层学到的是一般编辑策略还是训练任务的答案模式。

<a id="p27"></a>
## P27｜TextGrad: Automatic “Differentiation” via Text

**文献**：Mert Yuksekgonul 等，2024 首稿；2025 Nature 正式版本标题为 *Optimizing generative AI by backpropagating language model feedback*。[首稿](https://arxiv.org/abs/2406.07496) · [期刊原文](https://www.nature.com/articles/s41586-025-08661-4)。

**问题与方法**：复合 AI 系统的失败应归因到哪些组件？TextGrad 用语言模型产生针对计算图变量的反馈，沿依赖关系传播，再据此更新提示、代码或其他文本表示的对象。

**证据**：论文通过多种优化案例展示通用接口的适用性。这里的“梯度”是自然语言反馈的类比，不是传统可微函数的精确导数。

**边界**：反馈可能不准确，更新不保证降低真实损失；反馈生成、评价和变量表示依旧人为设计。跨领域展示不等于一个系统已经自主构建所有领域的验证器。

**连接**：承接 [P25 DSPy](#p25) 的模块化系统观；与 [P28](#p28) 对照信用分配式反馈传播与进化式候选选择；也可作为 [P30 ADAS](07_recursive_agents.md#p30) 的组件优化对照。

**研究启发**：测量语言反馈的归因准确率，比较指出具体错误与仅写“请改进”在等预算下的区别。

<a id="p28"></a>
## P28｜GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning

**文献**：Lakshya A Agrawal 等，2025 首稿，ICLR 2026 Oral；近期代表作。[原文](https://arxiv.org/abs/2507.19457)。

**问题与方法**：稀疏标量奖励会丢失轨迹中的信息。GEPA 阅读推理、工具调用与反馈，反思失败并提出提示修改；维护在不同样本上表现互补的候选，通过 Pareto 思路选择和组合经验。

**证据**：论文在所研究任务和模型配置下，以较少 rollout 获得有竞争力的结果。标题中的“can outperform”应按实验条件理解，不是提示优化普遍优于 RL。

**边界**：rollout 少不等于总成本必然低，反思模型、token、评估和搜索都应计入；主要演化对象是提示，外层优化器通常固定。

**连接**：汇合 [P23](#p23) 的语言反思、[P26](#p26) 的优化历史与 [P07](03_foundations.md#p07) 的多样性思路；与 [P59](#p59) 对照是否同时演化变异机制；适合成为代码 RSI 的强对照。

**研究启发**：在相同底座、工具、开发集与总成本下，先证明代码改写优于高质量提示优化，再声称更自由的搜索空间有必要。

## 三个适合作为科研基线的层次

| 层次 | 方法 | 必须控制的混杂 |
|---|---|---|
| 当前任务 | ReAct、Self-Refine | 工具反馈、多次尝试、token 数 |
| 跨尝试/跨任务 | Reflexion、Voyager | 记忆可见性、任务重用、技能检索 |
| 持久程序优化 | DSPy、OPRO、TextGrad、GEPA、Promptbreeder | 开发集搜索预算、候选选择、反思模型强度 |

这些方法的合理组合可以形成很强的固定改进器。如果一个新 RSI 方法只超过单轮提示，而没有超过上述固定改进器，证据仍不足以说明递归是收益来源。
