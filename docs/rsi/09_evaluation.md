# 09｜评价、反面证据与失效机制

[返回总览](README.md) · 本章收录 P41–P50。

RSI 的正面论文需要与本章配套阅读。闭环会反复放大评价信号，因此小偏差可能比单轮任务中更严重；但负面结果同样依赖条件，不能被扩大为“自改进不可能”。

<a id="p41"></a>
## P41｜Large Language Models Cannot Self-Correct Reasoning Yet

**文献**：Jie Huang 等，2023 首稿。[原文](https://arxiv.org/abs/2310.01798)。

**问题与方法**：严格检查内在自纠错：不提供外部正确性反馈，仅凭模型自身尝试修订推理答案。论文发现，在所研究模型和任务上，这种修订常常无效，甚至降低表现。

**贡献**：迫使研究者区分来自外部答案、反馈泄露或更多计算的收益，与真正识别自身错误的能力。

**边界**：这是特定时期模型和实验设置的结果，不是关于所有未来模型的不可实现定理；也不否定写作润色、工具辅助纠错或经过专门训练的纠错。

**连接**：与 [P22 Self-Refine](06_scaffolds.md#p22) 的设置差异必须同时看；[P42 SCoRe](#p42) 回应“纠错能力是否需要训练”；[P18 AZR](05_curricula.md#p18) 则加入环境锚点。

**研究启发**：报告四种转移：错→对、对→错、错→错、对→对，避免只展示少量成功修订例子。

<a id="p42"></a>
## P42｜Training Language Models to Self-Correct via Reinforcement Learning（SCoRe）

**文献**：Aviral Kumar 等，2024。[原文](https://arxiv.org/abs/2409.12917)。

**问题与方法**：离线模仿纠错轨迹容易遇到分布错配或退化为单一修订模式。SCoRe 在模型自己的多轮生成分布上进行在线 RL，通过训练阶段设计与奖励鼓励有效纠错。

**证据**：论文在数学与代码任务上报告自纠错改善，说明某些内在纠错局限可以通过专门训练缓解。

**边界**：训练阶段仍需要正确性信号；训练时有外部奖励、推理时无外部反馈并不矛盾。本篇改进的是纠错策略，不是训练算法自身。

**连接**：直接配读 [P41](#p41)，与 [P09 STaR](04_self_training.md#p09) 对照只学成功轨迹与学多轮修订；与 [P17 R1](05_curricula.md#p17) 对照显式训练纠错和一般推理奖励。

**研究启发**：将有效改错与保持正确答案同时纳入奖励，检查收益是否来自首轮表现下降后的“容易改进”。

<a id="p43"></a>
## P43｜Let's Verify Step by Step

**文献**：Hunter Lightman 等，2023。[原文](https://arxiv.org/abs/2305.20050)。

**问题与方法**：只判断最终答案，难以定位推理中的错误。论文比较结果监督与逐步过程监督，训练过程奖励模型，并发布 PRM800K 人工步骤标注。

**证据**：在论文的数学推理与候选选择设置中，过程监督有效。其结果涉及奖励模型和搜索/选择，不应被转述为单次无辅助生成的正确率。

**边界**：步骤标注有成本，过程模型也可能误判；在数学任务有效不保证所有开放任务都能定义正确步骤。它不是无人工监督的自训练。

**连接**：为 [P09 STaR](04_self_training.md#p09) 的正确答案筛选补充过程视角；可与 [P13](04_self_training.md#p13)、[P60](04_self_training.md#p60) 结合研究自评价，但需独立校准。

**研究启发**：对长程智能体轨迹，比较最终任务成功奖励与局部工具/子目标反馈，研究如何分配信用。

<a id="p44"></a>
## P44｜Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena

**文献**：Lianmin Zheng 等，2023。[原文](https://arxiv.org/abs/2306.05685)。

**问题与方法**：开放式回答难以用标准答案评分。论文研究强语言模型裁判与人类偏好的一致性，同时分析位置、冗长、自我偏好及推理能力限制等偏差。

**证据**：模型裁判在研究设置中能近似部分人类偏好，提供规模化评价手段；但这既不是事实核查保证，也不是对每个领域都有相同一致率的承诺。

**边界**：静态评价中表现良好，不代表能承受长期针对裁判进行的适应性优化。共同模型家族还可能共享盲点。

**连接**：是理解 [P13 Self-Rewarding](04_self_training.md#p13)、[P60 自教评价器](04_self_training.md#p60) 与 [P36 自动审稿](08_automated_science.md#p36) 的必要背景。

**研究启发**：随机交换答案顺序、控制长度、隐藏模型身份，并在长期优化中保留独立人工/规则审计子集。

<a id="p45"></a>
## P45｜SWE-bench: Can Language Models Resolve Real-World GitHub Issues?

**文献**：Carlos E. Jimenez 等，2023 首稿。[原文](https://arxiv.org/abs/2310.06770)。

**问题与方法**：代码片段生成不能充分衡量软件工程。SWE-bench 从真实仓库 issue 和对应修复构造任务，要求模型理解代码库并提交可通过评测的修改。

**证据与价值**：原始论文建立仓库级任务与执行评价，为 [P40 SWE-agent](07_recursive_agents.md#p40)、[P32 SICA](07_recursive_agents.md#p32)、[P33 DGM](07_recursive_agents.md#p33) 提供重要实验场景。

**边界**：原版、Lite、Verified、论文自选子集不能混用；测试通过并不覆盖所有真实质量。公开任务可能进入模型训练或被研究者反复优化。

**连接**：由静态代码基准走向长程工具交互；与 [P47 RE-Bench](#p47) 对照修复现有仓库与研究工程问题。

**研究启发**：记录具体 task IDs、镜像/依赖、版本和测试可见性；按仓库及时间划分任务，减少近重复泄露。

<a id="p46"></a>
## P46｜AgentBench: Evaluating LLMs as Agents

**文献**：Xiao Liu 等，2023 首稿，ICLR 2024。[原文](https://arxiv.org/abs/2308.03688)。

**问题与方法**：用多个交互环境评价语言模型的推理、决策与长期行动，而非只做单轮问答。论文包含八类环境并分析典型失败。

**证据与价值**：提示长程决策和指令遵循是独立瓶颈，单一代码成绩无法代表所有智能体能力。

**边界**：聚合分数可能掩盖环境差异；框架、解析器和工具错误可能影响结果。AgentBench 本身是评价平台，不是自改进算法。

**连接**：与 [P21 ReAct](06_scaffolds.md#p21) 的行动结构相接；[P56 AgentGym](05_curricula.md#p56) 从多环境评价进一步走向训练和演化。

**研究启发**：把环境执行失败、协议失败与规划失败分开统计，避免把接口修复误称为通用推理进步。

<a id="p47"></a>
## P47｜RE-Bench: Evaluating frontier AI R&D capabilities of language model agents against human experts

**文献**：Hjalmar Wijk 等，2024。[原文](https://arxiv.org/abs/2411.15114)。

**问题与方法**：AI 自动研发能力需要真实研究工程评价。RE-Bench 提供七个开放式机器学习研发环境，并与人类专家在不同时间预算下进行比较。

**证据**：论文显示相对表现与预算密切相关，短时间内快速尝试的优势未必延续到更长时间。具体比较属于原论文时期与模型，不应写成当前排行榜。

**边界**：少量研究工程任务不能覆盖科学价值、研究方向选择或长期研究计划；人类工时与模型墙钟时间也不等价于相同总计算成本。

**连接**：为 [P35 AlphaEvolve](08_automated_science.md#p35) 与 [P36–P37 AI Scientist](08_automated_science.md#p36) 提供更接近 AI 研发的评价参照；与 [P51](10_frontier.md#p51) 共同强调“预算内改进能力”。

**研究启发**：画完整质量—成本/时间曲线，比较最佳样本、平均样本和多次尝试汇总，避免仅选对某方法有利的一个预算点。

<a id="p48"></a>
## P48｜Scaling Laws for Reward Model Overoptimization

**文献**：Leo Gao、John Schulman、Jacob Hilton，2022 首稿。[原文](https://arxiv.org/abs/2210.10760)。

**问题与方法**：代理奖励分数提高是否代表真实质量提高？用一个“金标准”奖励模型模拟真实偏好，训练较弱代理，再通过 RL 或 best-of-N 优化代理，观察两者分数关系。

**证据**：进一步优化代理可能损害金标准得分；论文量化其随优化强度及模型/数据规模的变化。

**边界**：金标准也属于合成实验装置，不是无误的人类真实效用。结果揭示机制与规律，不能直接给出任意 RSI 系统的崩溃阈值。

**连接**：[P13](04_self_training.md#p13) 和 [P60](04_self_training.md#p60) 需要评价器独立审计；[P32–P33](07_recursive_agents.md#p32) 可能对固定基准过拟合；[P53](10_frontier.md#p53) 研究更主动的反馈污染。

**研究启发**：同时画内部奖励和独立质量曲线，检查二者何时分离；停止规则必须依据独立选择协议，而非内部奖励无限上升。

<a id="p49"></a>
## P49｜AI models collapse when trained on recursively generated data

**文献**：Ilia Shumailov 等，Nature 2024；早期预印本标题为 *The Curse of Recursion*。[期刊原文](https://www.nature.com/articles/s41586-024-07566-y)。

**问题与方法**：连续用上一代模型产生的数据训练下一代，会发生什么？论文通过概率模型分析与生成模型实验研究分布信息逐代流失，特别是尾部样本的遗失。

**证据**：在所分析的递归数据使用条件下，误差可积累并出现分布退化。这是长期自训练必须考虑的反面证据。

**边界**：不能推导为“任何合成数据训练都必然失败”；是否替换真实数据、样本规模、筛选和新环境信息都影响结论。原文另有 2025 年符号更正，推导时应使用更正版本。[更正说明](https://www.nature.com/articles/s41586-025-08905-3)。

**连接**：约束 [P08–P14](04_self_training.md) 的长期推论，与 [P50](#p50) 必须成对阅读；[P19 R-Zero](05_curricula.md#p19) 还需额外考虑伪标签质量，二者机制不能混为一谈。

**研究启发**：除平均准确率外测量低频能力、分布覆盖和策略多样性；一个平均分上涨的模型也可能丢失尾部能力。

<a id="p50"></a>
## P50｜Is Model Collapse Inevitable? Breaking the Curse of Recursion by Accumulating Real and Synthetic Data

**文献**：Matthias Gerstgrasser 等，2024。[原文](https://arxiv.org/abs/2404.01413)。

**问题与方法**：递归训练中，用新合成数据替换旧数据，与持续保留并累积数据，是否导致相同结局？论文比较两种设置，并在可分析的线性模型框架中研究误差界。

**证据**：在研究的实验与理论条件下，累积真实和历代合成数据可以避免替换式训练中的坍塌。这修正了“递归必然失败”的过强表述。

**边界**：不代表无限累积数据没有成本，或所有领域都安全；重复、相关错误、错误标签与长尾覆盖仍需独立处理。

**连接**：针对 [P49](#p49) 的条件做对照；与 [P24 Voyager](06_scaffolds.md#p24) 的经验保存有概念相似性，但生成分布坍塌与技能遗忘不能等同。

**研究启发**：将回放比例、真实数据保留、样本多样性和预算匹配作为实验变量，避免把增加训练数据量造成的收益全部归给“防坍塌机制”。

## RSI 实验最低报告表

这是本笔记建议的研究协议，不是上述论文共同采用的标准。

| 维度 | 至少记录 |
|---|---|
| 系统边界 | 底座模型版本；哪些组件允许改，哪些固定 |
| 数据划分 | 开发任务、选择任务、密封审计任务；划分粒度 |
| 反馈来源 | 真值、执行、仿真、裁判、人工；是否同源 |
| 持久性 | 哪些经验、提示、技能、代码跨任务保留 |
| 成本 | 提案、失败候选、评价、训练、推理、工具与人工干预 |
| 随机性 | 多个独立搜索种子；任务级与搜索级不确定性 |
| 对照 | 固定元智能体、等预算采样、仅提示更新、仅工具更新 |
| 元能力 | 相同初始任务智能体上，不同改进器产生后代的增益 |
| 泛化 | 新题、新仓库、新环境机制、新底座是否仍成立 |
| 退化 | 错误修订、评价漂移、长尾能力损失、版本损坏 |

不应在审计集上选择每轮最高分再报告那条曲线；这种做法让审计集变成开发集。若需要展示整条测试轨迹，应预先定义报告协议，并保留另一个最终确认集合。
