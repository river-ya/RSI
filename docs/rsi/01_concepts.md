# 01｜概念与统一框架

## 1. 首先定义系统边界

讨论 RSI 时，“自己”可能指基础模型，也可能指包含模型、提示词、记忆、工具和控制程序的智能体。固定模型权重并不排除系统级递归；反过来，更新权重也不自动构成递归。STOP 对“完整 RSI”的表述较严格，而现代智能体工作常采用系统层边界。写论文时应声明自己的边界，避免仅凭命名争论。[STOP 原文](https://arxiv.org/abs/2310.02304)、[现代智能体自改进综述](https://arxiv.org/abs/2607.13104)。

本笔记使用如下分析记号，属于综述组织工具，不是某篇论文的原始定理：

\[
S_t=(\theta_t,P_t,M_t,T_t,C_t,D_t,E_t,U_t).
\]

| 记号 | 含义 | 代表论文 |
|---|---|---|
| \(\theta\) | 模型参数 | STaR、ReST、SPIN |
| \(P\) | 提示词、示例和指令 | OPRO、DSPy、GEPA |
| \(M\) | 持久记忆与经验 | Reflexion、Voyager |
| \(T\) | 工具和技能程序 | Toolformer、Voyager、SICA |
| \(C\) | 编排代码和控制流 | ADAS、AFlow、DGM |
| \(D\) | 数据与任务分布 | Self-Instruct、Absolute Zero、R-Zero |
| \(E\) | 训练/搜索用评价器 | Self-Rewarding、Self-Taught Evaluators |
| \(U\) | 产生与选择改进的机制 | STOP、Promptbreeder、Hyperagents |

一般迭代可写成：

\[
S_{t+1}=U_t(S_t,F_t;B_t),
\]

其中 \(F_t\) 是反馈，\(B_t\) 是预算。关键检查不是有没有下标 \(t+1\)，而是 **\(U_t\) 是否也是可更新对象，以及被更新的部分是否实际参与后续改进**。

## 2. 四种容易混淆的进步

下表是本笔记的操作性划分，不是公认等级标准，也不表示各方法简单线性优劣。

| 类型 | 什么发生了变化 | 典型情况 | 还需要什么证据 |
|---|---|---|---|
| 输出修订 | 当前回答或解题轨迹 | Self-Refine | 是否在新的问题上留下可复用能力 |
| 持久自改进 | 权重、记忆、技能、提示词 | STaR、Voyager、GEPA | 是否只是固定优化器重复搜索 |
| 机制性递归 | 改进器、变异策略或自修改代码 | STOP、Promptbreeder、SICA、DGM、Hyperagents | 改过的机制是否比冻结机制更有效 |
| 持续加速 | 单位资源带来的改进能力持续增加 | 长期研究目标 | 多轮、等预算、跨任务、排除饱和与噪声的证据 |

“能修改代码”“已经改善代码”“改善后能更有效地产生下一代代码”是三个不同命题。允许修改的自由度，只说明搜索空间；实验效果还取决于反馈、预算和算法。Gödel Machine 的条件性证明、现代系统的实证结果也不能互换。[Gödel Machine](https://arxiv.org/abs/cs/0309048)、[DGM](https://arxiv.org/abs/2505.22954)、[Hyperagents](https://arxiv.org/abs/2603.19461)。

## 3. 每篇论文统一问八个问题

1. 改进对象是哪一部分？参数、回答、课程、工具还是改进器？
2. 谁提出修改？同一模型、历史版本、固定教师还是人工？
3. 谁提供质量信号？标签、执行环境、形式验证器还是模型自评？
4. 修改如何保留？训练、记忆、技能库、程序归档还是仅当前上下文？
5. 新版本是否参与生成后续版本？参与的是求解器还是元改进器？
6. 哪些部分固定？基础模型、任务集、奖励、搜索算法、人工筛选？
7. 预算如何计算？采样、评估、失败候选、训练和人工干预是否全部计入？
8. 提升在哪个集合上成立？开发集、选择集、独立测试集还是未见任务域？

## 4. 区分两类能力指标

任务能力可定义为 \(J(S;\mathcal T)\)：系统在测试任务分布 \(\mathcal T\) 上的期望质量。

元改进能力可以用一个**建议性实验指标**表示：

\[
G(U;S_0,B,\mathcal T)=
J(\operatorname{Select}_{val}(\operatorname{Run}(U,S_0,B));\mathcal T)-J(S_0;\mathcal T).
\]

比较 \(U_0\) 与 \(U_t\) 时，应使用相同起点 \(S_0\)、相同预算 \(B\) 和不参与选择的测试集。否则，后代起点更好、调用更多或评价器更宽松，都可能伪装成元能力提升。Hyperagents 的 improvement@k 提供了相关实证思路，但本式不是其原式，增加了预算显式化的研究要求。[Hyperagents §5.2](https://arxiv.org/html/2603.19461v1#S5.SS2)。

对于得分有上限的任务，不应要求 \(J\) 永远指数增长。更合适的量可能是达到固定质量所需的总成本、适应新任务的样本效率、或在更难任务上的迁移增益。连续多轮正增益也不等同于加速。

## 5. 反馈的可信度需要按任务判断

形式验证器能证明的是给定形式规范内的性质；测试只能覆盖有限输入；仿真器可能存在现实差距；人工评价也会不一致。因而不能简单建立适用于所有任务的绝对排序。

对于有明确正确性的数学/代码任务，独立执行或证明检查通常比同源模型“觉得正确”更容易审计。对于写作或研究价值，规则验证不足以替代人类判断。建议同时记录信号的**独立性、覆盖度、可攻击性、成本和校准误差**。[Let's Verify Step by Step](https://arxiv.org/abs/2305.20050)、[LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)。

## 6. 三个常见误读

- **“零数据”**：通常指特定后训练阶段不使用人工题目/答案，不代表模型从未利用人类数据；环境设计、提示模板和预训练知识仍在。
- **“自博弈”**：AlphaZero 的精确胜负、SPIN 的人类示范对照、R-Zero 的伪标签课程，机制并不相同。
- **“自主科研”**：自动生成论文或改进训练基础设施，是闭环中的环节；还须展示成果如何回流并增强下一轮研究能力，才能支持更强 RSI 主张。
