# 07｜智能体代码与递归改进：核心阅读章

[返回总览](README.md) · 本章收录 P29–P33、P38、P40、P61。

这一章最接近用户关心的“agent + RSI”。重点不是程序能否被修改，而是修改后的程序有没有进入下一轮改进链。阅读时始终区分基础模型、任务智能体、元改进器和外部评价器。

<a id="p29"></a>
## P29｜Self-Taught Optimizer（STOP）: Recursively Self-Improving Code Generation

**文献**：Eric Zelikman、Eliana Lorch、Lester Mackey、Adam Tauman Kalai，2023 首稿，COLM 2024。[原文](https://arxiv.org/abs/2310.02304)。

**问题**：语言模型能改程序，那能不能改“负责改程序的程序”？

**方法**：从一个种子 improver 出发，它调用固定语言模型生成候选程序，用给定效用评价后选择结果。随后把 improver 自身作为待改程序，让它提出自己的新版本，再检查新 improver 在下游任务上的改进能力。

**证据**：在有限算法任务中，演化后的改进器优于初始改进器；生成策略包含不同的搜索思路。其关键实验对象是改进程序，而不是某一个最终答案。

**边界**：底座、效用函数和实验任务仍外部给定。作者自己说明冻结语言模型并不构成其定义下的完整 RSI；不能改写成基础模型已自主升级。有限任务上的元优化收益也不能推出无限递归。

**连接**：从 [P03 学习优化器](03_foundations.md#p03) 接到代码空间；与 [P59 Promptbreeder](06_scaffolds.md#p59) 都改变改进策略；[P32 SICA](#p32) 扩展到一般代码智能体，[P51 Hyperagents](10_frontier.md#p51) 更明确分离任务与元层。

**研究启发**：一个成本较低的 RSI 原型可以只允许改写候选生成/筛选器，而不是从完整操作系统级智能体开始。关键对照是冻结 improver 的等预算搜索。

<a id="p30"></a>
## P30｜Automated Design of Agentic Systems（ADAS）

**文献**：Shengran Hu、Cong Lu、Jeff Clune，2024 首稿。[原文](https://arxiv.org/abs/2408.08435)。

**问题与方法**：手工枚举提示链、反思模块和协作方式限制设计空间。ADAS 提出自动设计智能体这一问题，并用 Meta Agent Search 演示：固定元智能体读取历史设计与评价，编写新智能体的代码，测试并归档。

**证据**：论文研究多个推理/问题求解领域及跨模型、跨任务迁移，支持代码作为智能体设计表示的价值。

**边界**：代表性实现的元智能体仍固定。代码语言具有表达力，不代表实际实现可以在有限资源内探索所有设计，也不保证发现最优方案。“生成更好的 agent”与“生成器变得更强”应分开。

**连接**：承接 [P05 NAS](03_foundations.md#p05) 的自动设计思路；[P38 AFlow](#p38) 以树搜索组织工作流空间；[P32](#p32)、[P33](#p33) 将修改者本身放入候选链，是识别机制性递归的主要对照。

**研究启发**：ADAS 类固定元智能体应成为 RSI 实验的必备基线。若动态改进器没有超越它，不能仅凭“自修改”说明递归有效。

<a id="p38"></a>
## P38｜AFlow: Automating Agentic Workflow Generation

**文献**：Jiayi Zhang 等，2024 首稿。[原文](https://arxiv.org/abs/2410.10762)。

**问题与方法**：把智能体工作流写成带有模型调用节点与连接关系的代码，利用蒙特卡洛树搜索、执行反馈和历史经验组织结构修改。

**证据**：论文在六个基准上展示自动工作流搜索的收益，并讨论效果与推理成本。它表明搜索结构可以是性能来源，而非所有收益都来自基础模型。

**边界**：工作流空间、算子与搜索机制仍有预设；最终小模型推理便宜，不等于发现该工作流的总成本也便宜。自动优化不自动等于递归优化。

**连接**：与 [P30 ADAS](#p30) 对比历史档案驱动设计与显式树搜索；与 [P25 DSPy](06_scaffolds.md#p25) 对比流程编译；为 [P33 DGM](#p33) 提供固定搜索器对照。

**研究启发**：在相同候选数和评价预算下，比较树搜索、种群搜索与固定元智能体；先剥离搜索算法改进与元能力学习。

<a id="p31"></a>
## P31｜Gödel Agent: A Self-Referential Agent Framework for Recursive Self-Improvement

**文献**：Xunjian Yin 等，2024 首稿，ACL 2025；ACL 标题使用 “Recursively Self-Improvement”。[arXiv](https://arxiv.org/abs/2410.04444) · [ACL 原文](https://aclanthology.org/2025.acl-long.1354/)。

**问题与方法**：固定模块和固定更新流程会约束智能体设计。Gödel Agent 提供读取、调整自身逻辑的机制，让 LLM 根据高层目标与反馈动态修改行为与部分流程。

**证据**：论文在推理和智能体任务上报告收益；其贡献是把自身逻辑作为可操作对象，而不是只迭代回答。

**边界**：它受 Gödel Machine 启发，但采用语言模型判断和实验反馈，不执行原理论要求的收益证明。仍需逐项查看可修改接口、底座调用与预算；不同模型配置的收益不能全部归因于递归。

**连接**：思想上连接 [P02](03_foundations.md#p02)；与 [P30](#p30) 对照固定元程序；与 [P32 SICA](#p32) 对照运行中受接口约束的逻辑调整与较完整代码库的修改。

**研究启发**：针对“可改范围”做递增实验：只改提示、改工具、改控制流、改元过程；测新增自由度的净收益与搜索成本。

<a id="p40"></a>
## P40｜SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering

**文献**：John Yang 等，2024。[原文](https://arxiv.org/abs/2405.15793)。

**问题与方法**：普通终端接口不一定适合模型。SWE-agent 设计适配智能体的文件导航、查看、修改和测试接口，提升其解决仓库级问题的能力。

**证据**：在 SWE-bench 和 HumanEvalFix 上展示接口设计带来的收益。它是理解后续自改代码智能体“到底改好了什么”的关键背景。

**边界**：原始系统的接口主要由人设计，不是 RSI。其历史成绩只对应当时模型和评估协议，不能作为今日性能基准直接引用。

**连接**：承接 [P21 ReAct](06_scaffolds.md#p21) 的交互；使用 [P45 SWE-bench](09_evaluation.md#p45) 的任务；[P32](#p32)、[P33](#p33) 尝试自动发现相似的接口与上下文改进。

**研究启发**：如果 RSI 候选学到的只是早已知道的文件编辑技巧，应把“自动重新发现有效设计”与“提出新方法”分开陈述。

<a id="p32"></a>
## P32｜A Self-Improving Coding Agent（SICA）

**文献**：Maxime Robeyns、Martin Szummer、Laurence Aitchison，2025。[原文](https://arxiv.org/abs/2504.15228) · [v2 方法与实验](https://arxiv.org/html/2504.15228v2)。本笔记引用可核对的 arXiv 版本，不根据二手条目断定其会议状态。

**问题与方法**：让代码智能体编辑自己的完整实现，并让更好的版本继续负责改进。SICA 维护历史代码与成绩，每轮从档案中选择效用最好的智能体，分析既往结果，实施新修改，再评估入库。

**效用设计**：原文把质量、时间和 API 成本纳入选择；因此“最优父代”不只是正确率最高。模型权重保持固定，变化体现在工具、上下文管理与代码逻辑。

**证据**：摘要报告 SWE-bench Verified 上从 17% 到 53% 的提升；正文 §4 明确这是固定随机抽取的 **50 道题子集**，另有 LiveCodeBench 和合成任务。不能写成完整 SWE-bench Verified 的公开排行榜结果。

**边界**：反复用同一集合选择版本会产生适应性过拟合；超时和初始接口水平会影响收益空间；当前任务表现最高的父代，也未必最会产生更好的后代。

**连接**：[P30 ADAS](#p30) 的固定元智能体在这里被候选智能体自身替代；与 [P33 DGM](#p33) 的关键对比是父代选择与探索方式；[P51](10_frontier.md#p51) 提醒把任务能力和元能力拆开。

**研究启发**：对同一批父代分别测当前得分与固定预算下的后代收益，研究二者是否相关。这比只画最高分随迭代增长更接近 RSI 的核心问题。

<a id="p33"></a>
## P33｜Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents（DGM）

**文献**：Jenny Zhang、Shengran Hu、Cong Lu、Robert Lange、Jeff Clune，2025 首稿。[原文](https://arxiv.org/abs/2505.22954) · [v3 正文](https://arxiv.org/html/2505.22954v3)。

**问题与方法**：单条不断自改的路径可能陷入局部最优或损坏自己。DGM 维护不同智能体的档案，从历史候选中选择父代，利用其代码能力产生新版本，再以编码任务检验；允许从非当前最优版本出发寻找“踏脚石”。

**递归性在哪里**：执行任务与编辑自身实现都是代码活动，因此改好的工具和控制程序可能同时帮助后续自修改。底座模型不更新；父代采样、外部基准等也仍有固定部分。它以经验检验替代 Gödel Machine 的证明门槛。

**证据与协议**：原文设置包含 80 次迭代、冻结改进器对照与去掉开放探索的对照。摘要中的 SWE-bench 20%→50% 对应论文的子集/分阶段协议；v3 §4.2 描述从小子集筛选强候选，并在满足条件时扩到 200 题，不能等同于全量 Verified。Polyglot 的 14.2%→30.7% 是额外全量评价，须与搜索用 50 题的结果区分。[实验协议](https://arxiv.org/html/2505.22954v3#S4)。

**边界**：这些证据支持有界代码环境中的自修改与档案探索收益；没有证明任意领域的元改进能力会持续增加。更好的编码分数与更好的自修改能力存在任务重合，仍需跨域和元层指标。

**连接**：汇合 [P02](03_foundations.md#p02) 的自修改目标、[P07](03_foundations.md#p07) 的踏脚石思想、[P29](#p29) 的改进器优化及 [P30](#p30) 的代码设计；[P51 Hyperagents](10_frontier.md#p51) 明确讨论编码能力与自改能力未必跨域一致。

**研究启发**：同时保留质量、行为多样性和后代生产力；并用相同总成本与固定元智能体比较，检查优势究竟来自开放探索还是元层变化。

<a id="p61"></a>
## P61｜Huxley-Gödel Machine: Human-Level Coding Agent Development by an Approximation of the Optimal Self-Improving Machine

**文献**：Wenyi Wang 等，2025-10 首稿，ICLR 2026；简称 HGM。[原文](https://arxiv.org/abs/2510.21614) · [会议论文](https://openreview.net/pdf?id=T0EiEuhOOL)。

**问题与方法**：当前编码任务分数未必预测未来自修改潜力。论文把这一问题称为 metaproductivity-performance mismatch，并以谱系后代的表现构造 clade metaproductivity（CMP），估计该量来指导自修改树的搜索。

**证据**：作者比较自改系统的搜索效率、编码表现与迁移。题名中的 human-level 对应特定基准与人类工程化智能体结果的比较，不应理解为在一般软件工作中与人类工程师全面等价。

**边界**：真实 CMP 不可直接预知，需要估计；实际估计量与理想量的理论联系不能混同。后代获得的搜索资源、选择规则及成本口径会影响生产力估计，本文不将条件性分析转述为通用最优性。

**连接**：针对 [P32 SICA](#p32)、[P33 DGM](#p33) 的父代选择问题；与 [P51 Hyperagents](10_frontier.md#p51) 的 improvement@k 形成“谱系潜力估计”与“元改进能力测量”的互补；理论背景连接 [P02](03_foundations.md#p02)。

**研究启发**：不能再把“按后代潜力而非当前分数选父代”直接作为新贡献。可进一步检验不等预算、不同任务域和早期少样本下，生产力估计的校准与选择偏差。

## 核心系统横向比较

| 系统 | 主要可变对象 | 下一轮修改者 | 关键外部约束 | 最应补测的证据 |
|---|---|---|---|---|
| STOP | 改进器代码 | 演化后的 improver | 固定 LM、效用与任务 | 新任务上的改进器效率 |
| ADAS | 任务智能体程序 | 固定元智能体 | 设计接口与验证集 | 强固定改进器基线 |
| AFlow | 工作流代码/结构 | 固定搜索框架 | 算子、搜索规则、反馈 | 搜索成本与结构贡献 |
| Gödel Agent | 自身逻辑与行为 | 具自修改能力的智能体 | 接口、底座与目标 | 改动范围、同底座消融 |
| SICA | 自身代码库 | 档案中效用最好的版本 | 基准、效用、预算 | 父代分数与后代收益 |
| DGM | 自身代码及工具 | 从多样档案选择的版本 | 底座、外层采样与评估 | 元层迁移与长期独立测试 |
| HGM | 自修改树中的候选 | 按估计谱系生产力引导选择 | 估计规则、编码基准、资源 | 潜力估计的成本与迁移校准 |
| Hyperagents | 任务程序和元程序 | 元程序也可变化 | 外部任务/评价与资源 | 可复用元收益与累积证据 |

Hyperagents 详见 [10](10_frontier.md)。这张表是机制比较，不是排行榜。

## 一个适用于这些方法的研究用伪代码

以下是本笔记提出的实验骨架，不是对任一原算法的逐字复现：

```text
archive = {initial_agent}
冻结独立审计协议、底座版本和预算记账方式
重复直到总预算耗尽：
    parent = 按预定规则从 archive 选择
    proposal = improver(parent, 开发反馈, 历史档案)
    candidate = 在隔离副本中应用 proposal
    score = 在开发任务上评估(candidate)
    记录所有成功、失败、成本与代码差异
    按预定规则更新 archive
只按选择集选出候选
在不可被优化器访问的审计集上评估候选
```

比较组只改变 `improver` 是否允许更新，其他条件匹配；另设“只改提示”“只改工具”“更多独立采样”等对照。对长期重复试验，审计集也需要预先约定的更新与访问限制，不能无限查询同一个测试集。
