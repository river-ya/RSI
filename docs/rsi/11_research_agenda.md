# 11｜从文献走向可执行科研

[返回总览](README.md)

以下是根据本次检索整理的**待验证研究方案**，不是已证明结论，也不是已完成的新颖性审查。用户尚未提供 GPU、API 预算或研究周期，因此按资源层次给出选择，不承诺固定花费或论文录用。

## 1. 优先建议：固定底座，研究系统级元改进的可测收益

建议首先从提示/工具/代码层入手：更容易保存每次差异、做冻结组件消融，也不必先承担大模型后训练开销。选题要超过“我做了一个会改自己的 agent”，重点应落在机制、评价或成本上。

| 方向 | 更具体的问题 | 最近的必要对照 | 主要资源 |
|---|---|---|---|
| A 后代潜力与成本 | 在预算不均、早期少样本时，怎样可靠估计父代改进潜力？ | HGM、DGM、SICA、Hyperagents | 可执行小任务 + 多次搜索 |
| B 评价信号漂移 | 哪种外部校准能阻止内部奖励与真实质量逐代分离？ | Self-Rewarding、过优化、进步错觉 | 裁判调用 + 独立真值任务 |
| C 课程与验证共设计 | 相同验证预算下，什么课程能带来更大的域外收益？ | AZR、R-Zero、Agent0 | 可先无训练，后需后训练资源 |
| D 经验抽象与任务流 | 如何把失败修复转成跨任务可复用经验，同时减少负迁移？ | Reflexion、Voyager、AgentStream、CFOE | 持久记忆框架 + 任务流 |

## 2. 方向 A：成本约束下的后代潜力估计

**已有工作**：[HGM](07_recursive_agents.md#p61) 已研究任务表现与元生产力错配，并以 CMP 指导选择；[Hyperagents](10_frontier.md#p51) 已研究元能力评价。发现“当前高分父代未必最好”本身已经不是新贡献。

**可收窄的假设**：当父代扩展次数与执行成本不均时，直接汇总后代表现会混入资源分配优势；经成本和不确定性校准的选择策略，可能在相同总预算下更稳定地找到可迁移改进。

**最小实验**：

1. 固定一个底座与初始智能体，准备可执行的程序修复或算法任务，按题目家族/仓库划分开发、选择、审计集合。
2. 记录搜索树：每个父代、提案、代码差异、工具调用、真实成本、失败原因及后代成绩。
3. 比较当前分数贪心、均匀探索、DGM 风格选择、HGM/CMP 基线与拟议校准方法。
4. 另做一个受控实验：给不同父代相同的后代扩展预算，直接估计其生产力，检查选择器预测误差。
5. 在未参与开发的任务族复测，评价最终质量与达到固定质量的成本。

**指标**：固定预算下的测试增益、潜力预测校准、排序相关性、达到目标质量的成本、多次搜索成功率。不将 token、美元和墙钟时间混成同一个数；若使用综合指标，要公开权重并做敏感性分析。

**必须反驳的替代解释**：只是给某些父代更多机会；只增加了候选数；用测试分数选父代；基线实现过弱；算法在一个家族上搜索更久。

**失败也有价值的结果**：若潜力估计成本超过其节省的搜索成本，结论应是某些预算区间中复杂元估计不划算，而不是强行解释为“需要更大模型”。

## 3. 方向 B：演化评价器，但保留独立质量锚点

**已有工作**：[Self-Rewarding](04_self_training.md#p13)、[Self-Taught Evaluators](04_self_training.md#p60) 已让评价器学习；[奖励过优化](09_evaluation.md#p48)、[基准污染](10_frontier.md#p53)、[进步错觉](10_frontier.md#p64) 已揭示反馈失真风险。“增加一个更强裁判”本身不是充分创新。

**假设**：少量但针对分歧与高风险更新的独立验证，比同预算下随机校准或单一模型自评，更能抑制长期质量漂移。

**实验矩阵**：固定生成器/演化生成器 × 固定裁判/演化裁判；每格再比较无校准、随机校准、分歧驱动校准。所有组使用相同外部验证预算。

**适合起步的任务**：有可自动判定答案、但能让裁判只看到部分信息的代码或结构化推理。这样可以控制“裁判知道多少”，并在实验外测到真值。之后再研究开放式任务。

**关键指标**：真质量增益、裁判误差、错误接受/拒绝率、内部/外部评分差、每单位验证成本收益；同时测旧错误是否重新出现。

**消融与反证**：交换答案顺序、控制长度、使用异源裁判；若独立校准只是把更多真值泄露给训练系统，需匹配其他组可见的真值量。若曲线改善仅来自减少迭代次数，应比较同等候选搜索预算。

**新颖性核验重点**：继续检索 adaptive evaluation、evaluator drift、verification allocation、self-rewarding calibration；上述方向已有多篇直接相关工作，贡献应落到具体预算策略或因果实验。

## 4. 方向 C：从“困难题”改为“有学习价值的题”

**已有工作**：[POET](03_foundations.md#p07)、[AZR](05_curricula.md#p18)、[R-Zero](05_curricula.md#p19)、[Agent0](05_curricula.md#p20) 已研究课程与求解器共演化。提出 Challenger/Solver 双角色不是新点子。

**假设**：题目有效性、机制多样性与独立可验证性，比单纯把求解通过率推到中间区间，更能预测后续域外收益。

**两阶段实验**：先冻结求解器，比较各课程策略生成题目的有效率、重复率、难度分布和伪标签精度；仅在第一阶段可靠后，再做等训练 token 的参数更新或等调用预算的技能学习。

**对照**：固定题库、自生成随机课程、仅难度课程、难度+多样性课程、难度+验证置信度课程。严格匹配出题、解题和验证的总开销。

**指标**：每单位有效训练样本的未见任务收益，独立验证正确率，长尾能力覆盖，循环后退化率。课程自身的平均奖励只能作为诊断量。

**潜在混杂**：更难的题需要更长输出；筛选后各组有效训练量不同；生成器重复改写评测题；失败题可能只是歧义或无法执行。必须分别控制。

## 5. 方向 D：让失败经验跨任务迁移

**已有工作**：[Reflexion](06_scaffolds.md#p23) 提供语言记忆，[Voyager](06_scaffolds.md#p24) 提供技能程序；[AgentStream](10_frontier.md#p62) 与 [CFOE 研究](10_frontier.md#p63) 已直接检查任务流和失败经验的泛化。

**假设**：带适用条件、证据来源与反例的经验，比只保存自然语言总结，更能在机制相近的新任务中复用，并减少跨域负迁移。

**实验设计**：每条经验包含错误原因、触发条件、修复动作、支持轨迹、反例；比较原始轨迹、普通摘要、结构化经验、可执行技能四种载体。控制存储 token 与检索预算。

**三层测试**：原失败任务重试、同错误机制的新任务、不同机制新任务。再把任务以顺序和交错方式输入，观察经验积累后是否变差。

**指标**：修复率、同机制迁移、跨机制负迁移、记忆检索命中与误用率、经验删除后的因果性能变化。

**可能贡献**：应证明某种经验表示改善可迁移性，或者清楚界定它何时无效；不能仅把它命名为“长期自演化记忆”并展示单个成功例子。

## 6. 一套建议的共同实验规范

开发任务用于生成修改；选择任务用于挑选版本与调超参数；审计任务由实验驱动器独立保管。三个用途不能只改名称而共享同一任务实例。对于多轮研究，还要防止研究者反复看审计结果后手动调方法。

建议先用小规模试验估计单次候选成本和结果方差，再据此确定正式搜索次数与独立重复数。不要把“3 个种子”当万能充分样本量；随机性很大时，增加任务数未必代替增加独立搜索重复。

伪代码、代码版本、数据划分、失败日志和全部成本都应保存。独立测试要在冻结候选上进行；不能把失败运行从成本或性能统计中删掉。生成代码仅在实验副本中执行，评测标准与审计数据应与可编辑代码分离，以保证结果可解释。

## 7. 最有说服力的论文叙事

“我们观察到一个明确可重现的瓶颈 → 排除若干替代解释 → 提出针对性机制 → 在等预算下改善它 → 说明何处仍失败”。

比起笼统宣称实现 RSI，一个在强基线、干净协议和跨任务测试下成立的窄结论，更适合作为第一项研究成果。
